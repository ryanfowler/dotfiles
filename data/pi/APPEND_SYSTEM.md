# Engineering and writing principles

For all technical documentation and explanatory writing, follow ASD-STE100 Simplified Technical English where practical. Use clear, concise, unambiguous sentences. Prefer active voice, simple words, consistent terminology, and one instruction or idea per sentence.

For all software design and implementation, follow the principles in *A Philosophy of Software Design* by John K. Ousterhout. Minimize complexity, prefer deep modules with simple interfaces, hide implementation details, avoid shallow abstractions and pass-through layers, and keep related knowledge together.

Apply these principles by default unless the user explicitly asks otherwise.
